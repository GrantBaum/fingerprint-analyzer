DB is for holding prints in a database. The database is local on the computer to keep in the spirit
of processing locally for security and speed reasons. None of it goes on GitHub.
    - index.csv holds one row per print: ID, name, finger (could be unknown), path to the source image,
      path to the skeleton, path to the template, the date it was added and the pipeline version
    - raw/ holds the original image files exactly as they came in, named by ID (0001.tif ...)
    - skel/ holds the skeleton images, named by ID (0001.png ...)
    - tmpl/ holds the templates, named by ID (0001.tmpl ...)
The ID for the source image, skeleton and template always match so that they can be paired.

The templates will have just minutiae and coordinates, and that is what will be compared against.
if a match is found, the processed and unprocessed photos can be manually reviewed by the technician to
ensure validity or at least get eyes on the subject. The software suggests. The examiner decides.

OUT holds results that are waiting. After a print is analyzed, everything about it sits in
out/<print name>/ until it is catalogued (moved into db/) or discarded. out/eval/ holds the
results of fpmatch eval, including scores.csv.

DATA holds prints to work on. Not committed. Running fpmatch with no arguments lists everything in data/
by number, so a print can be dragged in and picked. A folder inside data/ can be catalogued all at once.

SRC holds all the code. It can be ran by compiling with the make command and then running with the proper arguments
specified in the README.md documentation.
    - fingerprint.hpp has the shared structs and every function declaration
    - image_processing.cpp processes the image: load, normalize, mask, binarize, thin
    - enhance.cpp cleans up the ridges before binarize: orientation, frequency, Gabor filter
    - minutiae.cpp finds the minutiae (endings, bifurcations, dots, short ridges, spurs, lakes and
      crossovers), filters out fakes, saves and loads templates
    - matching.cpp lines two templates up and scores them
    - database.cpp catalogues, searches and discards
    - main.cpp runs everything: the command line, the start menu, the case menu, fast mode batches and eval
    - ui.hpp is for the cool and clean UI

DOCS holds any additional info (like this file)
    - briefing.md explains how every stage works, for learning and for teaching the class
